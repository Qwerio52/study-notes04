#### \# 第5章 函数和代码复用 学习笔记

本章围绕函数展开，学习如何将重复代码封装为函数，实现代码复用。内容涵盖自定义函数、函数调用、参数传递、变量作用域、匿名函数lambda、递归函数以及模块化设计思想，是从简单脚本编写过渡到工程化编程的关键章节。



##### \## 知识点总结



##### \### 1. 自定义函数 def

语法格式：

```python

def 函数名(参数列表):

&#x20;   函数体

&#x20;   return 返回值

遵循先定义，后调用的规则；只有调用函数时，内部代码才会执行。

return 用于向调用方返回结果，同时终止函数；没有写 return 时，函数默认返回 None。



##### 2\. 函数参数分类

位置参数：按照顺序一一对应进行传参。

默认参数（可选参数）：为参数设置默认值，调用时不传该参数则自动使用默认值。

注意：不推荐使用列表等可变对象作为默认参数，容易出现意料之外的 bug。

可变参数

\*args：接收任意数量位置参数，打包成元组

\*\*kwargs：接收任意数量关键字参数，打包成字典

关键字传参：调用时 func(a=1, b=2)，传参顺序可以自由调整。



##### 3\. 匿名函数 lambda

适用于简短单行表达式逻辑，无需定义函数名。

语法：lambda 参数: 返回表达式

常配合 sorted()、map()、filter() 使用。

限制：仅支持表达式，不能写循环、分支代码块等复杂逻辑。

示例：

python

运行

add = lambda x,y: x + y



##### 4\. 参数传递机制

Python 参数传递为对象引用传递：

不可变类型（int、str、tuple）：函数内部修改，不会影响外部原始变量。

可变类型（list、dict、set）：函数内对对象内容修改，外部原对象同步变化。



##### 5\. 局部变量与全局变量

局部变量：定义在函数内部，作用域仅限函数内部，函数执行结束后自动销毁。

全局变量：定义在函数外部，在整个文件范围内都可以访问。

如果想要在函数内部修改全局变量，需要用 global 关键字声明。

开发建议：尽量少使用全局变量，会增加代码调试难度、提高耦合度。



##### 6\. 递归函数

定义：函数在内部调用自身。

两个必备条件：

基线条件（终止条件）：满足条件就停止递归，防止无限递归栈溢出。

递归条件：把大问题拆解成规模更小的同类子问题。

典型场景：阶乘、斐波那契数列等分治类问题。

缺点：递归深度存在上限，过大深度会栈溢出；相比循环，额外的函数调用会带来性能开销。



##### 7\. 代码复用与模块化设计

抽象：隐藏内部实现细节，只对外暴露调用接口，使用者只关心入参和返回结果。

模块化：按照功能拆分函数、拆分.py文件，一个模块负责一类功能。

模块化优势：

消除重复代码，一处修改多处生效；

结构清晰，便于阅读、调试、团队协作；

降低代码耦合，方便单独测试。

Python 标准库本质就是模块化思想的体现，直接 import 即可复用成熟代码，不用重复造轮子。



##### 8\. 案例：七段数码管绘制

基于 turtle 绘图，将绘制单段数码管、绘制数字、移动光标等功能拆分为独立函数，体现单一职责原则：一个函数只负责一件事。



##### 学习心得体会

&#x20;   在学习本章之前，我写代码习惯把所有逻辑全部堆在主流程中，遇到重复功能就复制粘贴代码。代码变长之后，修改一处就要同步改动很多地方，维护成本很高，也很容易引入 bug。函数封装让我真正理解了抽象与复用的编程思想。

&#x20;   函数的核心价值就是把独立的功能封装起来。调用者只需要知道怎么传参、拿到什么结果，不需要关心内部实现细节，这也是大型项目开发的基础思维。

&#x20;   参数部分是本章比较容易踩坑的地方。一开始我很难区分位置参数、可变参数，也不理解可变对象传参带来的副作用。练习之后明白了 Python 引用传递的特点，可变对象在函数内修改会影响外部，写代码的时候需要多加留意。同时我也记住，尽量不去滥用全局变量，全局变量会让程序的数据流向变得混乱，后期很难排查问题。

&#x20;   递归给我的感受很特别。递归代码往往非常简洁优雅，用很短的代码就能表达分治思路，但是它对逻辑思维要求更高。如果终止条件写错，就会直接栈溢出崩溃。递归适合思路天然可以拆分的问题，但并不是所有场景都适合，很多时候循环方案会更加稳定高效。

&#x20;   模块化设计思想不只是写几个函数这么简单。它教会我写代码前先做拆分：把复杂需求拆解成一个个小功能，每个功能用一个函数实现。这种思路可以让代码层次分明，可读性更强，也为之后学习导入模块、多文件项目开发打下基础。

&#x20;   总的来说，这一章是我从 “跑通一段代码” 转向 “写规范、可维护代码” 的转折点。函数、封装、抽象这些思想，会贯穿后续所有程序开发的学习。
